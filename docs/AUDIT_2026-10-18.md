### Found and fixed after the plan was written

- **The fork's request parser read past the received data** (SEC-12), found
  by the new fuzz target. Fixed in fork `1753a8b`.
- **Upstream v1.73.7 regressions caught during the rebase.** `/info` called an
  optional callback unchecked, and `/action` asserted a current video. Both
  could crash the receiver; guarded in fork `63c903f` and `fd73e8a`. The
  `conn_teardown` callback the plugin needs was restored (`45b01bb`).
- **The updater's install lock had a race** when two installers took over a
  stale lock. It now uses `flock()` (`8dc49c0`), with a stress test. This was
  new code in 2.6.0, so no released version had the bug.
- **The media player could show a pre-roll frame** after a paused backward
  seek on a loaded machine (an intermittent CI failure of `media-ts-seek`).
  The race is fixed (`c810423`), with the regression test
  `media-ts-seek-race`.
- **Users can now control what AirPlay video may fetch.** The new **AirPlay
  video** setting offers Off, Only from the sending device (the default) and
  From any web address (`f1c3b4d`, `7753461`; fork `40a3881`). Every refusal is
  logged and shown on the Status line.
- **The properties panel was reorganised:** an "AirPlay receiver" box and a
  collapsible "Advanced settings" box (`1e9d88f`).
- **4.9 was finished:** a page-local video's spool file (up to 128 MiB) is
  written on a worker thread, not the network thread, and playback starts
  once it is written (fork `cebc806`). The large-blob test now also makes the
  write 1.5 s slow, and the worst `/playback-info` wait stays at 16–27 ms
  (51–58 ms before, seconds on slow disks); CI enforces the budget again.
- **httpd's `run_mutex` was never initialised** (upstream too), so the flag
  that stops the server thread was unprotected; ThreadSanitizer found it
  (fork `679c3c5`).
- **A request could crash OBS through libplist** (Critical, the same class
  as SEC-1). libplist's string getters assert that a string's length equals
  its `strlen()`; a UTF-16 string with a zero code unit breaks that, and the
  release libplist was built with asserts, so one `POST /play` aborted OBS.
  Found at once by the new request fuzz target (A9). Every plist from a
  sender is now checked before parsing (fork `ac3dc65`,
  `uxplay/lib/plist_checked.h`), the release libplist is built with
  `NDEBUG`, and the protocol smoke sends such a request (it aborted the
  receiver without the fix).
- **BUG-15 fixed:** the receiver advertises 48 kHz formats, but decoding and
  the RTP clock assumed 44.1 kHz stereo. SETUP's `audioFormat` now sets the
  RTP clock rate (fork `5b7c816`) and the decoder's rate, channels, bit depth
  and frame length; the AAC AudioSpecificConfig and ALAC cookie are built for
  them (the 44.1 kHz ones are byte-identical to the old constants). Unit
  tests decode AAC-LC at 48 kHz and ALAC at 44.1/48 kHz, 16/24-bit.
- **A9 fuzzing of request bodies done:** `obs-airplay-fuzz-requests` runs
  request sequences (`/play`, `/action`, playback controls, RTSP SETUP with
  `audioFormat`) through the real handlers on a socketless connection (fork
  `f12a037`); 1.2 million sequences ran clean under ASan after the fix.
- **llhttp's `__builtin_ctzll(0)`** in its NEON scan is written out (fork
  `4e13ea7`); UBSan is clean.

## Executive summary

The plugin's core data paths are in good shape. Every FFmpeg, VideoToolbox, CoreVideo and libobs resource was traced across error and reinit paths without finding a leak, the lock order is acyclic, NV12 from VideoToolbox reaches OBS without a CPU conversion, timestamps are correct, and the updater's download/stage/swap logic is careful and well tested. The fork's own C additions are bounds-checked and typed.

The serious problems sit at the edges:

1. **One unauthenticated HTTP request crashes OBS.** `POST /fp-setup2` with an empty body dereferences a NULL body pointer. Inherited from upstream, but reachable because the fork enables the AirPlay-video HTTP surface. **[verified]**
2. **One byte on one TCP connection hangs the receiver** until the attacker disconnects (blocking read loop on the single HTTP thread). Upstream fixed this on 2026-10-01; the fork is eight months behind upstream. **[verified]**
3. **Renaming the receiver is a use-after-free.** `dnssd_unregister_*` frees the name/MAC strings while the HTTP thread may still be building `/info` from them. **[verified]**
4. **The media player can hang the HTTP thread or OBS shutdown**: `stop()` notifies the pause condition variable without holding the mutex (lost wake-up), and the `std::thread` member is touched from three threads with no synchronisation. **[verified]**
5. **The self-update chain has no trust anchor beyond the GitHub account.** Releases are ad-hoc signed and the "code seal" check is `codesign --verify` with no designated requirement, so anyone who can publish a release asset ships native code into OBS, bypassing Gatekeeper. **[verified]**
6. **Any LAN device can make the OBS host fetch arbitrary http(s) URLs**, with no host allowlist and no TLS certificate verification (FFmpeg's `tls_verify` defaults to off). **[verified]**
7. **Unauthenticated memory/disk exhaustion**: 129 MiB request bodies × 12 connections, plus up to 10 × 128 MiB spool files. **[reviewed]**
8. **Build and release hygiene**: tracked stale `build/` directory, configure-time downloads of unpinned `simde master`, the submodule pinned to a fork feature branch, GPL-2.0 declared where GPL-3.0 is shipped, no CI, 1 of 4 smoke tests registered with CTest, broken `diagnose.sh`, and port documentation (5000) that does not match the code (7000/7001). **[reviewed]**

Performance is reasonable in the mirror path (one unavoidable libobs copy per frame). The URL-playback path does one extra full-frame hardware→CPU copy per frame and has a single-thread demux→decode→sleep→present design with no look-ahead. Startup pays a synchronous `open` round trip for the BLE helper and a 67–80 ms lazy VideoToolbox session creation on the first connection.

The README's claim that "a malformed request from the local network can no longer crash OBS" is not currently true (item 1).

# Part A — Findings

Severity: **Critical** = remote crash/code execution or data loss with trivial trigger; **High** = memory-safety bug, hang, or security control that does not do what it claims; **Medium** = real bug or weakness with a narrower trigger, or meaningful UX/perf defect; **Low** = hardening, quality, or polish.

## A1. Security (network surface, updater, supply chain)

### SEC-1 — Critical — Empty-body `POST /fp-setup2` crashes OBS [verified]
`uxplay/lib/http_handlers.h:573-576`
```c
int req_datalen = 0;
const unsigned char *req_data = (unsigned char *) http_request_get_data(request, &req_datalen);
logger_log(raop->logger, LOGGER_ERR, "... version is 0x%2.2x", req_data[4]);
```
`http_request_get_data` returns `request->data`, which is NULL when no body was received (`http_request.c:328-334`). Dispatch at `raop.c:494`. Trigger: `POST /fp-setup2 HTTP/1.1`, `X-Apple-Session-ID: x`, `Content-Length: 0`, from any LAN host, no pairing. A 1–4 byte body gives a heap over-read instead. Note the fork's `fast_connect` advertises FairPlay-capable features (`0x0E427FFFF7`), which makes real iOS devices more likely to send this request too.
**Fix:** `if (!req_data || req_datalen < 5) { http_response_init(response, "HTTP/1.1", 400, "Bad Request"); return; }`.

### SEC-2 — High — Blocking initial read loop lets one connection stall the receiver [verified]
`uxplay/lib/httpd.c:492-514`. Sockets are never set non-blocking and have no `SO_RCVTIMEO` (grep across `lib/` finds timeouts only on the NTP and mirror sockets). After `select()` says readable, the loop calls blocking `recv()` until 8 bytes have arrived. Sending one byte and holding the connection parks the single `httpd_thread`, which serves RTSP, mirror control and AirPlay video for all peers. Upstream fixed this ("httpd: remove blocking while-loop for peeking initial 8 bytes" and "add timeout = 60s for removing dead connections", 2026-10-01).
**Fix:** port the two upstream commits, or set `SO_RCVTIMEO` on accepted sockets and treat a short peek as "wait for more data".

### SEC-3 — High — Update chain: any ad-hoc signature passes, digest and URL come from the same document [verified]
`src/plugin-updater.mm:169, 360` run `/usr/bin/codesign --verify --deep --strict` with no `-R=` requirement. `scripts/package-macos.sh:277-280` ad-hoc signs releases by default. `plugin-updater.mm:218-219` takes `browser_download_url` and `digest` from the same `releases/latest` JSON. The bundle-identifier check reads the attacker-controlled `Info.plist`. The extracted bundle carries no quarantine attribute, so Gatekeeper never evaluates it. Consequence: whoever can create a release in the GitHub repo (leaked token, compromised CI, collaborator) or MITM TLS with a CA-trusted cert can install native code into OBS. What is done right: https-only, host pinned to `github.com`, size cap, strict version parsing, no downgrade, args passed as argv arrays, absolute tool paths.
**Fix (pick one):** (a) sign releases with a Developer ID and verify with `SecStaticCodeCheckValidityWithErrors` against a pinned requirement (`anchor apple generic and certificate leaf[subject.OU] = "<TEAMID>" and identifier "com.lzlamian.obs-airplay"`); or (b) stay ad-hoc but publish a minisign/Ed25519 signature of the zip as a second release asset and verify it with a public key compiled into the helper. Also check the URL path prefix `/LZlamian/OBS-AirPlay-Plugin/releases/download/`.

### SEC-4 — High — Unauthenticated SSRF with no TLS verification [verified]
`uxplay/lib/http_handlers.h:1196-1199` allows any `http://`/`https://` Content-Location; there is no host/IP/port allowlist, so loopback, link-local (`169.254.169.254`), RFC1918 routers and any port are accepted. The text/parameters `/play` form (`:1763-1801`) needs no session ID. `src/media-player.cpp:522, 821, 1485` set `protocol_whitelist=http,https,tcp,tls,crypto` and `max_redirects=8` but never `tls_verify`, and FFmpeg's TLS defaults to no verification. `/playback-info` acts as a success oracle. The sender-hosted form pins the host to the peer IP but allows any port 1–65535.
**Fix:** reject loopback/link-local/multicast/unspecified targets and, for non-peer hosts, non-standard ports; set `tls_verify=1` (expose a "allow self-signed" toggle if needed); consider accepting only the stateful `/play` form (uuid + session ID).

### SEC-5 — High — Memory and disk exhaustion from unauthenticated bodies [reviewed]
`uxplay/lib/http_request.c:28,132-158` caps one body at 129 MiB; `httpd.c:155` allows 12 connections; `http_handlers.h:30-31` allow 129 MiB per `/action` and 128 MiB per spooled item, with up to 10 items (`raop.h:27`). Peak ≈ 12 × 129 MiB of `realloc`'d buffers plus plist data copies, plus up to 1.28 GB of spool files in `$TMPDIR`, with no per-IP or global budget. Bodies are consumed 1 KiB per `recv()` on the single HTTP thread (≈134k iterations for one 128 MiB clip), starving `/playback-info`, `/rate`, `/scrub`.
**Fix:** default body cap ≈16 MiB, raised only for `/action` on a connection whose session already has `reverse_media_pending`; a global budget across connections; 64 KiB receive buffer (see PERF-5).

### SEC-6 — Medium — Blocking `send()` on the HTTP thread; no `SO_NOSIGPIPE` [reviewed]
`uxplay/lib/fcup_request.h:99-108`, `httpd.c:597-604`, `http_handlers.h:1889-1901`. A sender that opens the PTTH channel and never reads it, or any LAN host that requests `GET /master.m3u8` and stops reading, fills the kernel send buffer and blocks the thread forever. `fcup_request` does not loop on short writes. SIGPIPE is survived only because OBS ignores it process-wide.
**Fix:** `SO_SNDTIMEO` or non-blocking sockets with a write queue, `SO_NOSIGPIPE`, loop on partial sends, restrict the HLS proxy handler to loopback peers.

### SEC-7 — Medium — No session binding: any peer can stop/scrub another sender's playback [reviewed]
`uxplay/lib/raop.c:606-617` (new in fork), `:426-427`, `http_handlers.h:380-402, 830-836`. `/stop`, `/rate`, `/scrub`, `/play`, and merely opening-then-closing an AirPlay-typed connection are honoured from any peer. The only session check is an `assert` compiled out by `-DNDEBUG`.
**Fix:** bind the AirPlay-video session to the peer address that issued `/play`; ignore control requests from other peers; replace the assert with a real check.

### SEC-8 — Medium — Staged update is re-checked only for "any seal" and "newer"; no lock around the swap [reviewed]
`src/plugin-updater.mm:352-376`, `src/airplay-ble-discovery.mm:151-153`. At quit the helper installs whatever sits at the predictable path `<plugins>/.obs-airplay.update/obs-airplay.plugin` after only the seal check and a version comparison; `checkStagedBundle` (identifier, version == asset, arch, min OS) runs only at stage time. Cross-user exposure exists if the plugin lives in a group-writable `/Library/.../plugins` (the pkg installs there, and the writability test is `isWritableFileAtPath`). Two helpers (two OBS instances, or crash + relaunch) can interleave the swap: one deletes `previous.plugin` while the other's rollback depends on it. `previous.plugin` is deleted immediately on success, so there is no rollback if the new version fails to load.
**Fix:** re-run `checkStagedBundle` at install; require staging dir owned by the current uid, mode 0700; `O_CREAT|O_EXCL` lock file around the swap; keep `previous.plugin` until the next successful OBS start; only self-update bundles under `$HOME`.

### SEC-9 — Medium — Fork is 8+ months behind upstream UxPlay [reviewed]
Base `1e7a199` is 2026-01-28. Relevant upstream fixes since: recv error handling (#503, #506, #508), httpd select rework, assert cleanups, HLS playlist NULL guard, two memory-leak fixes in `airplay_video.c`/plist, llhttp callback cleanup (addresses SEC-12), and the two DoS fixes in SEC-2. The fork's `http_handlers.h` rewrite will conflict with upstream's "rearrange handler_play".
**Fix:** rebase the fork onto upstream master; push an immutable tag (see BUILD-4).

### SEC-10 — Medium — `fast_connect` advertises capabilities the receiver cannot service [reviewed]
`uxplay/lib/raop_handlers.h:139-168, 478-490`, `dnssd.c`. Skipping `pair-setup` loses no security in no-PIN mode (it authenticates nothing; `pair-verify` is key agreement only, and the PIN path is untouched). But advertising `AppleTV5,3` / features `0x0E427FFFF7` claims FairPlay-protected video, which draws `/fp-setup2` (SEC-1) and large protected-HLS requests.
**Fix:** after SEC-1, mask the feature bits the plugin does not implement; document why pair-setup is skipped.

### SEC-11 — Low — Media trace logs sender URLs and session IDs into the OBS log [reviewed]
`uxplay/lib/media_trace.h`, `src/uxplay-integration.cpp:58-72`. Opt-in (`OBS_AIRPLAY_MEDIA_TRACE=1` or flag file), writes no files of its own, never logs pairing or AES material. When on, it logs the first 160 chars of signed `Content-Location` URLs (query tokens), `X-Apple-Session-ID`, `X-Apple-Device-ID`, peer IP; this contradicts the comment at `raop.c:388-393`. Bounded per request (24 KB) but not per time. `httpd.c:537-545` logs the first PTTH reply line unconditionally at INFO.
**Fix:** redact query strings; say in docs that trace logs should not be pasted into public issues (INSTALL.md and QUICKSTART.md currently ask users to paste whole logs plus `ifconfig` and Wi-Fi name).

### SEC-12 — Low — `on_url` over-reads past the recv chunk [reviewed]
`uxplay/lib/http_request.c:62` `strncpy(request->protocol, at + length + 1, 8)` reads up to 9 bytes past the data when the request line is split across chunks. Outcome is a misrouted request, not corruption. Upstream reworked these callbacks 2026-09-30.

### SEC-13 — Low — Spooled reverse-fetched MP4 opened without a protocol whitelist [suspected]
`src/media-player.cpp:1483-1487` applies the whitelist only when `is_http_url()`; the spooled temp file is opened with FFmpeg's default nested protocols (`file,crypto,data`). The path itself is safe (mkstemp, 0600, validated dir). A crafted MP4 with relative `dref` entries could make FFmpeg read other files in the temp dir; they would only be decoded, not exfiltrated.
**Fix:** `protocol_whitelist=file` and leave `enable_drefs` off for the spooled path.

### SEC-14 — Low — Residual NULL paths once asserts are compiled out [reviewed]
`http_handlers.h:1870, 1888-1890` (`get_master_playlist(hls_get_current_video(raop))` can receive NULL), `:1501-1518` (`airplay_video_init` OOM), `raop.c:426-427`. Defensive; replace each removed `assert` with a real check.

### SEC-15 — Low — Configure-time downloads are unpinned and write into the source tree [reviewed]
`CMakeLists.txt:67-187`: `simde` from `refs/heads/master.tar.gz` and OBS tarballs with no `EXPECTED_HASH`; `file(COPY)` and `file(WRITE)` into `CMAKE_SOURCE_DIR/obs-headers`. Dormant while `obs-headers/` is tracked, but runs on any checkout missing it, and a failed simde download is only a warning. See BUILD-1.

## A2. Memory safety, crashes, hangs (plugin code)

### MEM-1 — High — Receiver rename frees DNS-SD strings the HTTP thread is still reading [verified]
`src/uxplay-integration.cpp:737-745` calls `dnssd_unregister_raop/airplay(old_dnssd)` before `raop_set_dnssd(raop_ref, new_dnssd)`. `uxplay/lib/dnssd.c:483-486`: once both services are unregistered, `free(dnssd->name); free(dnssd->hw_addr);` and the TXT records are deallocated. Meanwhile `raop->dnssd` still points at `old_dnssd`, and `raop_handlers.h:102-146` reads `dnssd_get_raop_txt/hw_addr/name(raop->dnssd)` on the HTTP thread for every `GET /info`, which iOS polls continuously while the Screen Mirroring sheet is open. The "retire the old context" scheme at `:747-758` does not help because the fields are freed by unregister, not destroy. `dnssd_destroy` (`dnssd.c:277-287`) does not free `name`/`hw_addr`, so the start-failure paths (`uxplay-integration.cpp:586, 601, 632, 640, 676`) also leak them.
**Fix:** move `raop_set_dnssd(raop_ref, new_dnssd)` before the unregister calls, and change `dnssd_unregister_*` to not free `name`/`hw_addr` (free them in `dnssd_destroy`). Then the retire scheme covers the remaining window.

### MEM-2 — High — Media player `stop()` has a lost wake-up that can hang the HTTP thread or OBS exit [verified]
`src/media-player.cpp:669-675`: `stop_requested.store(true); state_cv.notify_all();` without `state_mutex`. The paused wait at `:1030-1056` checks `stop_requested` under the lock and then `state_cv.wait(lock)` with no predicate and no timeout. If the store+notify lands between the check and the wait, the worker sleeps forever and `stop()` blocks in `worker.join()`. Every other notifier (`seek`, `setRate`, `pauseForPlaylistRemoval`) notifies under the lock. Trigger: `/rate 0` then `/stop` back-to-back; or OBS shutdown while an item is paused.
**Fix:** take `state_mutex` around the store in `stop()` (or `{ std::lock_guard l(state_mutex); } state_cv.notify_all();`), and make the paused wait a predicate wait, optionally with `wait_for(250ms)`.

### MEM-3 — High — `std::thread worker` is read/written from three threads with no synchronisation [verified]
`src/media-player.cpp:666, 673-674`. `play()` (HTTP thread) assigns `worker`; `stop()` runs from the HTTP thread, the deferred-clear thread (`uxplay-integration.cpp:147-148`), the UxPlay mirror thread via `video_reset` (`:455-459`), and the OBS main thread (`:808`). Two concurrent `join()`s, or assignment to a joinable thread, is `std::terminate`. `play()` also resets `stop_requested` at `:665` before spawning, so a concurrent `stop()` can be silently undone. Trigger: TEARDOWN/`video_reset` racing a `/play` for the next item (the comment at `uxplay-integration.cpp:461-463` says iOS does exactly this).
**Fix:** one `control_mutex` held for the whole of `play()`/`stop()` (join outside `state_mutex` but inside `control_mutex`); join the deferred-clear thread in `UxPlayIntegration::stop()` before touching the player. Remove the dead `worker.get_id() != this_thread` guard.

### MEM-4 — Medium — Stale I420 frame geometry after a failed allocation → `sws_scale` into NULL planes [verified]
`src/h264-decoder.cpp:386-396` writes `format/width/height` into `m_frame_i420` before `av_frame_get_buffer`; on failure the next frame compares equal, skips allocation, and `sws_scale` writes through `data[] == nullptr`. Only reachable on the non-I420/NV12 software or transfer path (10-bit HEVC, 4:2:2).
**Fix:** set the fields only after a successful `av_frame_get_buffer`, or zero them on failure.

### MEM-5 — Medium — `obs_module_load` can return false after starting a thread and registering a source [reviewed]
`src/plugin-main.cpp:168, 188, 277-280`. On an exception libobs will not call `obs_module_unload` but will `dlclose` the module at shutdown while the debounce thread is still running. Rare (`bad_alloc`).
**Fix:** never return false after side effects; clean up and return true, or start the thread after everything that can throw.

### MEM-6 — Low — `updateServerName` does not check `m_running`; `start()`/`stop()` mutate `m_raop`/`m_dnssd` without `m_mutex` [reviewed]
`src/uxplay-integration.cpp:695-704, 804-824`. Safe today only because unload joins the debounce thread before `stop()`.

### MEM-7 — Low — Unchecked `av_*_alloc` in `run()`; raw owning pointers [reviewed]
`src/media-player.cpp:1587-1596, 1763-1773`. Every exit path currently frees correctly (traced), but the next inserted `return` will leak. Wrap in `unique_ptr` with deleters as `ResilientHttpIo` already does.

### MEM-8 — Low — Sender-supplied double converted to `int64_t` without finiteness check [reviewed]
`src/media-player.cpp:1113, 1581` — `+inf` survives `std::max(0.0, x)`; out-of-range double→int64 is UB. Clamp with `std::isfinite` and to duration.

### MEM-9 — Low — `size_t → int` packet-size casts rely on caller bounds [reviewed]
`src/h264-decoder.cpp:498-502`, `src/audio-decoder.cpp:267-274`. Add `if (size > INT_MAX - AV_INPUT_BUFFER_PADDING_SIZE) return false;`.

## A3. Correctness bugs

### BUG-1 — Medium — Name debounce applies a stale name when the user reverts within 800 ms [verified]
`src/plugin-main.cpp:150-160` compares the new name with the *applied* name, not the *pending* one. Type "X" then Backspace within 800 ms → early return, pending "…X" is still applied; advertised name diverges from the setting until the next edit.
**Fix:** compare against `g_debounce_pending` when a debounce is in flight, or always enqueue and let `apply_server_name` early-return on equality.

### BUG-2 — Medium — Per-source settings drive global state; two sources fight [reviewed]
`src/airplay-source.cpp:59-64, 152-162`: `server_name`, `follow_sender_clock`, `log_latency_telemetry` are stored per source but there is one server per process; the last-updated source wins and the other's panel lies. No `OBS_SOURCE_DO_NOT_DUPLICATE`.
**Fix:** move these to module-level config (next to `mac_address.txt`) and show them in every panel, or set `OBS_SOURCE_DO_NOT_DUPLICATE` and refuse a second instance with an info row.

### BUG-3 — Medium — Seeks ignore `format->start_time` [reviewed]
`src/media-player.cpp:1113-1114, 1581-1582, 1653` pass a relative target to `av_seek_frame(format, -1, …)`, which is absolute. Positions are reported relative (`:389-390`). For MPEG-TS/HLS or edit-listed MP4, every seek lands `start_time` early and the discard logic decodes and throws away that much video, inflating scrub latency.
**Fix:** add `format_start_seconds` to the target in all three places.

### BUG-4 — Medium — Commands after end-of-stream are accepted but nothing serves them [reviewed]
`src/media-player.cpp:1755-1760` ends the worker; `seek()`/`setRate()` still mutate state, so `/playback-info` reports "playing at the new position" while the picture is frozen. Whether senders do this without a new `/play` is [suspected].
**Fix:** reject after `ended`, or treat a post-end seek as a restart.

### BUG-5 — Medium — Server start failure is invisible [reviewed]
`src/plugin-main.cpp:210-217`, `src/uxplay-integration.cpp:613-663`, `src/airplay-source.cpp:126-128`. Ports 7000 and 7001 busy, or `dnssd_register_*` failing (for example a name over 63 bytes → `kDNSServiceErr_BadParam`), yields only a log line and "Status: Server not running" or even "Status: Running" with nothing advertised. The BLE helper is launched regardless.
**Fix:** keep the failure reason and render it in `server_info`; cap `server_name` at 63 UTF-8 bytes; launch the helper only after `start()` succeeds. Document the macOS "AirPlay Receiver" setting, which occupies 7000 (see DOC-1).

### BUG-6 — Medium — Only one `avcodec_receive_frame` per packet; pts paired by call [reviewed]
`src/h264-decoder.cpp:514-521, 532-538`. 1:1 in practice with iOS streams, but a payload with two access units or an HEVC decoder holding a picture shows the second one late with the wrong timestamp or drops it in the EAGAIN drain.
**Fix:** loop `receive_frame` after each send, keep the newest picture, set `m_packet->pts` so the consumer can use `m_frame->pts`.

### BUG-7 — Low — `log_latency_telemetry` not applied on load [reviewed]
`src/airplay-source.cpp:64` applies `follow_sender_clock` in `create` but not the telemetry flag; libobs does not call `update` after `create`.

### BUG-8 — Low — `start()` ignores its `server_name` parameter [reviewed]
`src/uxplay-integration.cpp:80, 547-548`. Every launch advertises the default name first, then re-registers the saved name ~1 s later: an mDNS remove+add on every start, which the code's own comment says iOS handles badly. Persist the name in module config and pass it to `start()`.

### BUG-9 — Low — Invalid persisted MAC yields a split identity [reviewed]
`src/plugin-main.cpp:59` accepts any 17-char line; `uxplay-integration.cpp:537-542` falls back for dnssd but `raop_init2` still gets the bad string; the file is never rewritten.

### BUG-10 — Low — PPS-only updates are not remembered; fallback replays a stale PPS [reviewed]

### BUG-11 — Low — Colour matrix hard-coded to BT.709 for mirror video [reviewed]

### BUG-12 — Low — Audio decoder retries and logs at ERROR on every packet after an open failure [reviewed]

## A4. Performance

Baseline pipeline costs (hardware mirror path, per 1080p frame): 3 compressed-size copies (1 avoidable), 4 heap allocations, 0 decoded-frame copies in the plugin, 1 decoded-frame copy in libobs (3.1 MB), 7 lock pairs, no fixed sleeps. Audio: 5 heap allocations and 3 PCM copies per 10.9 ms packet.

### PERF-1 — Medium/High — URL-playback hardware frames are copied to CPU memory, then copied again by libobs [reviewed]
`src/media-player.cpp:1143-1152` `av_hwframe_transfer_data` on every frame. The mirror decoder already hands the locked CVPixelBuffer's NV12 planes to OBS directly (`h264-decoder.cpp:430-446`). Saves 3.1 MB/frame at 1080p, 12.4 MB at 4K, on the thread that is also the demuxer and clock. Size S–M.

### PERF-2 — Medium — VideoToolbox session created lazily on the first IDR, on the mirror thread: 67–80 ms cold [verified by harness]
`src/h264-decoder.cpp:143-150` creates only the hw *device* at load; the decompression session is built on the first SPS/IDR. A second session in the same process costs 4–16 ms, so ~60 ms is XPC warm-up. Warm it at plugin load off-thread with a canned SPS/PPS/IDR; log session-creation time separately. Size M.

### PERF-3 — Medium — Media player: single thread demux→decode→wait→present, zero look-ahead [reviewed]
`src/media-player.cpp:1043-1092, 1660, 1727-1733`. Any stall (HLS segment boundary, keyframe spike, reopen backoff up to 750 ms, 10 s `rw_timeout`) lands on the presentation deadline; audio has no lead, so OBS grows its global audio buffering. Decode into a bounded 2–3 frame queue and present from a dedicated thread. Size M–L.

### PERF-4 — Medium — BLE helper launch blocks `obs_module_load` [reviewed]
`src/airplay-ble-helper.cpp:50-63` `posix_spawn("/usr/bin/open")` + blocking `waitpid`, before the UxPlay server starts (`plugin-main.cpp:203`). Suspected 100–500 ms on OBS startup; measure, then spawn asynchronously and start UxPlay first. Size S.

### PERF-5 — Medium — 1 KiB HTTP receive buffer; whole body buffered before spooling [reviewed]
`uxplay/lib/httpd.c:356, 524`, `http_request.c:140-158`, `http_handlers.h:228-240`. Raise to 64 KiB (S, 60× fewer iterations); stream FCUP bodies to the spool file as they arrive (L). Overlaps SEC-5.

### PERF-6 — Medium/Low — Mirror decode and libobs copy run synchronously on the TCP receive thread [reviewed]
`src/airplay-server.cpp:179-259` holds `m_decoder_mutex` across decode and `obs_source_output_video`; ~2.4 ms + copy per 1080p frame during which the socket is not serviced and audio output (`m_sources_mutex`) waits. A one-slot "latest packet wins" mailbox feeding a decode thread preserves live semantics. Size M.

### PERF-7 — Low/Medium — Audio path allocator churn and identity resample [reviewed]
`src/audio-decoder.cpp:304-339` (`av_samples_alloc` per packet, `swr_convert` FLTP→FLTP at the same rate), `src/airplay-server.cpp:359-360` (two `std::vector<float>` per packet), `uxplay/lib/raop_buffer.c:208`. ~460 malloc/free per second. Hand `extended_data` straight to OBS when already FLTP stereo; reuse member buffers. Size S.

### PERF-8 — Low — Avoidable compressed-frame memcpy and two mallocs per mirror packet in UxPlay [reviewed]
`uxplay/lib/mirror_buffer.c:118-122` decrypts in place then memcpys; `raop_rtp_mirror.c:383-392, 440-449` malloc per packet. Decrypt out-of-place into a reusable buffer. Size S.

### PERF-9 — Low — Per-frame `blog(LOG_DEBUG)` formatted even when filtered [reviewed]
`src/uxplay-integration.cpp:899, 925` (~150 `vsnprintf`/s); `raop_rtp_mirror.c:335-340` four unconditional `snprintf` per packet. Remove or guard. Size S.

### PERF-10 — Low — Software fallback: slice threading with one thread per core on single-slice streams [reviewed]
`src/h264-decoder.cpp:134-135`. 10 idle threads per decoder on a 10-core Mac, no gain. Cap at 2–4; log `nal_count` once per stream to confirm slice count. Also `tune=zerolatency` at `:157-160` is an encoder option and is ignored (verified: left in the dict after `avcodec_open2`). Size S.

### PERF-11 — Low — Connected-but-idle mirror/audio threads poll every 5 ms [reviewed]
`uxplay/lib/raop_rtp_mirror.c:221-234`, `raop_rtp.c:439-453`: ~400 wakeups/s only to observe `running`. Self-pipe in the `select` set and a 250 ms timeout. Size S.

### PERF-12 — Low — Locked CVPixelBuffer held until the next decode call [reviewed]
`src/h264-decoder.cpp:433-434, 493`. Add `releaseFrame()` and call it right after `obs_source_output_video`. Size S.

### PERF-13 — Low — Build: no default build type, no dead-strip/visibility/LTO [reviewed]
A plain `cmake ..` compiles the plugin at `-O0`. Default `CMAKE_BUILD_TYPE=Release` when unset; add `-Wl,-dead_strip`, `-fvisibility=hidden`. Binary is 4.98 MB with static libcrypto+libplist. Size S.

### PERF-14 — Low — `blog()` and string formatting under `state_mutex` [reviewed]
`src/media-player.cpp:695-696, 783, 1010-1015, 1658-1662`. Log after releasing the lock.

### PERF-15 — Low — Uninterruptible backoff sleeps in AVIO callbacks [reviewed]
`src/media-player.cpp:559-561, 596-598`: up to 750 ms per read without polling `interrupted()`; delays item switches. Sleep in slices checking the stop flag.
